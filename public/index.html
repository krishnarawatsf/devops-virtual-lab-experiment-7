DevOps & Observability

Continuous Integration (CI): The automated practice of frequently merging code changes into a central repository, triggering automated builds, lints, and unit tests to detect bugs early.

Continuous Delivery (CD): Automatically prepares code changes for a release to production after passing all tests, requiring manual approval for the final deploy.

Continuous Deployment (CD): Goes one step further by automatically deploying every valid build directly into production without manual intervention.

Pod: The smallest deployable computing unit in Kubernetes, encapsulating one or more tightly coupled containers sharing network IP, storage volumes, and lifecycle.

Deployment: A declarative controller managing the desired state of Pods (replica count, rolling updates, rollbacks, and self-healing).

Service: An abstraction layer defining a stable logical set of Pods and a policy to access them via stable IP and DNS (ClusterIP, NodePort, LoadBalancer).

Prometheus Metric Scraping: Prometheus uses a pull-based architecture. It periodically queries configured HTTP /metrics endpoints over TCP, parsing time-series metrics (Counters, Gauges, Histograms) into its TSDB.

Why Grafana? Prometheus provides basic ad-hoc graphing and TSDB storage, while Grafana is an enterprise visualization platform featuring dynamic dashboards, multi-datasource querying, variable templating, and rich alerting panels.

Alertmanager: Handles alerts generated by Prometheus server rules. It deduplicates, groups, and routes alerts to downstream channels (Slack, Email, PagerDuty, Webhook) with silencing and inhibition rules.

Alert Rules: PromQL expressions configured in Prometheus (e.g., pod_cpu_usage_percent > 85 for 1m). When the condition is met for the duration of the for clause, Prometheus transitions the alert from Pending to Firing and pushes it to Alertmanager.

1. Latency: The time it takes to service a request (differentiating successful requests from errors).

2. Traffic: A measure of how much demand is being placed on your system (e.g., HTTP requests per second).

3. Errors: The rate of requests that fail (e.g., HTTP 500s or explicit system exceptions).

4. Saturation: A measure of system fullness, emphasizing most constrained resources (CPU, Memory, Disk I/O).
